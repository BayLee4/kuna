Canonical native import declaration design — SOURCE-ONLY PROPOSAL, NOT IMPLEMENTED

Observed failure and preserved contract
- The host callsite suite emits int printf(char*,...) / scanf(char*,...) declarations that conflict with the real SDK. Fix the declaration authority rather than patching SDK/preamble/C, inventing a target body, or discarding the native declaration unconditionally.
- Ghidra's retained char* source datatype is real source authority but is not a complete source-C header declaration: const is absent from its datatype vocabulary. Preserve the Function/HighFunction declaration and the actual variadic CALL ABI.
- Current native Direct contract has entry + Rc<FuncProto>, not library identity. Native declaration emits that prototype literally. Canonical C projection needs a separate imported-library fact, not a change to source authority or machine effects.

Evidence from installed Ghidra 12 sources
1. Features/Base/lib/Base-src.zip:ghidra/app/plugin/core/analysis/ApplyDataArchiveAnalyzer.java:98-117 applies ApplyFunctionDataTypesCmd with SourceType.IMPORTED.
2. Same archive, ghidra/app/cmd/function/ApplyFunctionDataTypesCmd.java:370-385 passes only FunctionSignature to ApplyFunctionSignatureCmd.
3. ApplyFunctionSignatureCmd.java:210-253 copies return/parameter datatypes, convention, varargs, noreturn into Function; it does not retain FunctionDefinition/archive identity on the Function. A SourceType.IMPORTED bit does not prove which header supplied a signature. A primitive parameter's SourceArchive is not function provenance.
4. Framework/SoftwareModeling/lib/SoftwareModeling-src.zip:ghidra/program/model/symbol/ExternalLocation.java:30-85 supplies actual library name, original imported name, symbol, source, external address; Function.getThunkedFunction(true) resolves the linkage target.
5. Features/Decompiler/lib/Decompiler-src.zip:ghidra/app/decompiler/DecompileCallback.java encodeResult collapses a Library namespace to global. HighFunction.encode in SoftwareModeling emits Function name/id, address and prototype but no library provenance. This must be extended; the native decoder cannot recover it from current global names.
6. ExternalSymbolResolverAnalyzer uses actual imported project libraries to resolve UNKNOWN symbols against required libraries. Library.UNKNOWN is a real unknown, not an implicit libc alias.
7. CLI loader/format/mod.rs ImportSym contains addr/name/kind only. Existing LibProtoPass is a lossy ABI-signature table, not a canonical-header authority: Ty::CharPtr has no qualifier; printf/scanf entries use it. libcsigs retains import-only/collision guards but still reduces real headers to the same vocabulary.
8. Installed SDK /Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/usr/include/_stdio.h:271 declares int scanf(const char * __restrict,...); standard stdio declarations retain const. Header qualifiers cannot be reconstructed from Ghidra char*.

Chosen model and trust boundary
- Keep an exact-address ImportedFunctionIdentity outside FuncProto/type inference: original library identity, original imported symbol, platform/object ABI, concrete linkage/external symbol identity, and current source signature snapshot. No name-only lookup, basename-substring heuristic, symbol-prefix stripping without platform import rules, datatype-name authority, or SourceType.IMPORTED-only shortcut.
- A small canonical library model registry is source-C declaration knowledge. It binds supported exact provider identities/platforms and imported symbols to a canonical C function declaration plus the erased ABI signature already modeled by the engine. This is an explicit library model, not proof inferred from a printf spelling. It must never match a mapped machine body, same-named local definition, an UNKNOWN library, an unresolved ambiguous import, renamed emitted symbol, or a mismatching current source signature.
- Initially required canonical descriptors are the actual printf/scanf declarations exercised by the user, not a blanket promise that every existing lossy model is C-compatible. Standard declaration descriptors can be extended independently with measured source/header evidence. No generic guessed const-on-char-pointers rule: e.g. sprintf's destination is mutable.
- Emit the canonical qualified declaration, e.g. int printf(const char *p0,...), only after an exact import receipt and whole source-ABI match. Top-level restrict on the parameter does not affect function type compatibility; const on pointee is required. Prefer an explicit canonical declaration to substituting an include: it stays within the existing declaration artifact schema and does not introduce standard FILE/header ownership collisions. Existing SDK includes in the test consumer remain untouched. No cast, alternate ABI call, wrapper target, or symbol redirection.
- A native import receipt authorizes source-C spelling only. It cannot make an incomplete machine summary complete, waive native ABI/call argument checks, or be used for a mapped-body provider.

Producer changes (maintained producer delta only)
- Add HighFunction.java to the existing SoftwareModeling source extraction and maintained patch. At encode(), inspect the actual Function and recursively resolved external thunk target. Obtain ExternalLocation via the external manager and its Symbol, never infer a library from the displayed Function name.
- Encode one optional dedicated imported-function element inside the same function record as its source prototype. Fields: exact queried/emitted linkage entry, actual external symbol ID/address, original imported name, current external label, exact library identity, source enum, platform/ABI identity, program/source revision scope. Existing Program revision and source identity discipline is reused; numeric wire IDs/schema revision require a single reviewed reservation with the core owner before patching.
- Only emit import provenance for real external/thunk linkage. A real local body cannot carry it. UNKNOWN/absent provider is encoded as no canonical authority, not libc. Signature provenance is the exact adjacent source prototype plus program revision, not an arbitrary trusted C string. No arbitrary host-supplied C text enters the native declaration.
- Do not patch archive-application code or invent a persistent canonical-signature flag: Ghidra does not retain that provenance today. Authentic imported provider metadata plus an explicit model is the boring available authority.

Native receiver and call publication
- infra/remote_provider.rs: decode the optional import record alongside RemoteFunction, validate duplicates/address/symbol scope, materialize it into exact-entry RemoteFunctionFacts. No global name cache. Stock records without the extension remain legitimate absence.
- Host context query exposes imported identity at an exact function entry. CLI context uses an equivalent loader-owned exact-entry map; both return the same immutable structure to native call proof.
- The native direct contract snapshots the receipt together with its retained Rc<FuncProto>. native_contract_matches compares current import receipt as well as existing ABI equality. native_declaration accepts an optional validated canonical model; otherwise it retains current exact source behavior. required_artifacts passes the validated receipt, not a string extracted from call.get_name().
- Registry matching validates return type, arity, variadic boundary, calling convention, pointer width and all fixed parameter semantic types after removing only qualifiers absent from the recovered ABI model. A source override at the callsite does not redefine the imported target's declaration. The existing native variadic-site proof is still required.
- Artifact identity includes canonical model identity/import provenance in addition to source ABI, so two providers or changed library/source records cannot collide. Retained Java Publication revision checks reject old support after library/thunk/signature edits. A failed fresh match falls back to the literal current declaration or refuses incompatibility; it never reuses the old canonical receipt.
- Emitted native declaration stays declaration-only (no fake existing-body receipt). Existing callable support consumer protocol need not grow a new artifact kind merely to carry the qualified spelling.

CLI producer requirements (cannot claim current ImportSym is sufficient)
- Extend ImportSym with optional exact provider identity, retaining Import vs Export distinction. Populate from actual format import resolution: PE import descriptor DLL plus thunk identity; Mach-O binding library ordinal plus LC_LOAD_DYLIB and import symbol; ELF dynamic symbol version requirement (versym -> verneed library), or an actual resolved-library binding. An ELF DT_NEEDED list alone is not a per-symbol provider proof. Unversioned/unresolved ELF providers remain unknown unless resolved against real loaded library metadata.
- Propagate this field through AnalysisOutput/commit to the exact-entry context map; do not park it in the by-name prototype map. Existing prototype model decisions remain independent. Existing --define-function name declarations cannot synthesize imported-library identity.
- Canonical model selection uses target platform/ABI, never the build host's libc. Standard printf/scanf qualified declarations are portable across the supported C implementations only once actual import and ABI validation succeed; vendor alias symbols require their own measured model entries, not unchecked prefix replacement.

Truthful host fixture migration
- Existing synthetic external_function builds Library.UNKNOWN and manually assigns char*. Changing that string to libc without an imported object is not acceptable evidence.
- Build a genuine small native executable which includes the actual SDK stdio.h, defines caller functions only, and links actual printf/scanf. Disable builtin substitution so the binary retains the calls. No handwritten callee implementation. Load that file using existing pyghidra.open_program import/analyze pattern; let the importer/resolver produce real ExternalLocations. On ELF, import/load the actual required libc into the project and run the normal resolver when the loader leaves UNKNOWN; do not overwrite the library assignment in the test.
- Locate the caller functions and their actual call sites from imported symbols/Listing, then run the same FormatStringAnalyzer. Preserve source fingerprint before/after and the fixed+closed override properties, actual argument values/types and variadic first slot. The source addresses may differ because this is an actual imported executable, not fabricated fixed-address code.
- Actual emitted fragment and actual whole Publication compile unchanged against the SDK and execute against the genuine native libc. Preserve printf output65/1234605616436508552 and return length; scanf consumes65/-7, returns2, leaves ! followed by EOF. Separate unchanged consumer drivers own assertions, not callee replacements. This design requires runtime proof of actual imported provider metadata before freezing any permanent fixture rewrite; source inspection alone has not observed it.
- Negatives: same-spelled mapped local function never matches; UNKNOWN import remains noncanonical; source argument/return/convention/vararg edit revokes; library change/retarget/rename revokes; old Publication fails stale revision check. Positive native identity is not license for arbitrary pointer casts or for replacing full source editing semantics.

Review/implementation boundary
- This is a concrete design, not an applied patch or a claim that available metadata already suffices. No production edits/native build/test runs were made for this investigation.
- Genuine host importer/provider metadata must be established on the real linked binary, especially ELF UNKNOWN resolution, before applying the producer/native-loader/consumer changes.
